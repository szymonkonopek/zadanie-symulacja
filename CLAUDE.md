# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Repository nature

This is **not a code repository**. It holds the deliverables for a Polish university assignment ("Zadanie symulacja") on building a simplified epidemic simulation. The whole "implementation" lives inside an Excel workbook — there is no source tree, no build/test/lint, and no toolchain.

All three files are in Polish:

- `Symulacja zadanie 1.docx` — the task brief (parameters, rules, deadline).
- `uproszczony model epidemii.xlsx` — the actual simulation model. Single sheet with a per-tick recurrence (row N depends on row N−1).
- `Uproszczony model symulacyjny epidemii.pptx` — accompanying slide deck.

When the user asks to "change the model", "fix a formula", or "tweak a parameter", they mean the `.xlsx`, not code.

## Domain model (read this before touching the spreadsheet)

The simulation is age-cohort-based with a SIR-like compartmental disease. One simulation tick = one "umowna jednostka czasu" (u.j.c.). Population starts at 488 animals.

Disease lifecycle per animal:
1. **Faza 1 (ca)** — asymptomatic carrier, infectious.
2. **Faza 2 (cb)** — symptomatic, still infectious.
3. Outcome: recovery → **temporary immunity (o)** lasting one tick, or **death**.
   Each stage lasts exactly one tick.

Other dynamics:
- Reproduction starts at age 2. Birth rates: ages 2–4 → 15±2%, ages 5+ → 10±1%.
- Probability that newborns are sick is proportional to the share of sick in the parent cohort.
- Mortality is age-banded: young (1–3) 20±5%, middle (4–5) 30±7%, old (6+) 50±15%. Average lifespan 6±1 u.j.c.

### Spreadsheet column legend

Polish abbreviations used as column headers in row 1 are not self-explanatory. From the brief + formulas, the convention is `<state>(t)` for count and `p<state>(t)` / `s<state>(t)` for inflow/outflow (przyrost / spadek):

| Col | Header | Meaning |
|-----|--------|---------|
| A | t | tick |
| B/C/D | z, pz, sz | healthy susceptible: count, inflow, outflow |
| E/F/G | o, po, so | recovered with temporary immunity |
| H/I/J | ca, pca, sca | sick — phase 1 (asymptomatic carriers) |
| K/L/M | cb, pcb, scb | sick — phase 2 (symptomatic) |
| N/O | u, pu | deaths (cumulative / new) |
| Q | pch | probability of infection ≈ (ca+cb)/total |
| R | śca | expected new phase-1 infections |
| S/T | (helper) | expected vs. rounded death/transition counts |
| V/W | (helper) | random-draw mortality fractions and applied deaths |

The recurrence pattern is roughly: `B(t) = B(t-1) + C(t) - D(t)`, with C/D pulling from neighboring compartments one row up. If you change a formula, propagate the same edit down the whole column — the spreadsheet does not use structured table references.

## Working with the Office files

The `Read` tool will not render `.docx` / `.xlsx` / `.pptx` usefully. To inspect contents from the shell:

```bash
# Extract docx/xlsx/pptx (they are zip archives)
unzip -q "uproszczony model epidemii.xlsx" -d /tmp/xlsx_extract
# Text:     word/document.xml (docx), ppt/slides/*.xml (pptx)
# Formulas: xl/worksheets/sheet1.xml + xl/sharedStrings.xml
```

Editing the binary files in place is not practical from the CLI. If the user wants formula changes, either (a) describe the change precisely so they can apply it in Excel, or (b) ask whether they want the model re-implemented as a script (e.g. a Python notebook) alongside the workbook — don't assume.

## Language

Respond in Polish when the user writes in Polish (matches the brief). Keep variable names / column references in their Polish form (`ca`, `cb`, `pch`, etc.) — renaming them would desynchronize the brief, slides, and workbook.

## Task-1 deliverable (added 2026-05-17)

`model epidemii (kohorty wiekowe).xlsx` is the response to Task 1 in the brief: a full age-cohort stochastic implementation (the existing `uproszczony` workbook only models aggregate dynamics). 18 sheets, all simulation logic lives in formulas (`RAND` / `NORM.INV` / `BINOM.INV`). Press F9 to draw a fresh trajectory; the `MonteCarlo` sheet contains a stub + manual instructions for wiring an N-replication Data Table.

Sheet roles:
- `Założenia` — single source of truth: birth/death tolerances, `h_nat(a)` table from N(6, 1) hazard, initial state, order-of-operations notes, defined-name targets (`mu_r_24`, `sig_m_13`, `h_nat_tbl`, etc.).
- `z`, `o`, `ca`, `cb` — compartment counts, 31 × 10 (t × age). Identical row/col convention for clean cross-sheet sums.
- `pch`, `r_st`, `m_st`, `pca`, `pu`, `urodz`, `urodz_ch`, `nat_z/o/ca/cb` — per-tick intermediate draws and counts.
- `Wyniki` — per-tick aggregates + chart + summary stats + defined-name targets for the MC sheet.
- `MonteCarlo` — Data Table scaffold (manual setup).

The workbook is regenerated by `build_model.py` (one-shot openpyxl builder; edit constants at top and re-run). `verify_model.py` is a Python re-implementation of the same per-tick logic — running it confirms invariants (population conservation, non-negativity, lifespan ≈ 6) that should also hold in the spreadsheet.
